Security Policy

Supported Versions

This website is maintained as a static GitHub Pages project. Security updates are applied only to the current version of the website published from the main branch.

Version

Supported

Current main branch

Yes

Older commits, forks, or archived copies

No

Reporting a Vulnerability

If you discover a security vulnerability affecting this website or repository, please report it privately by email:

aelshal-omfs@g.ecc.u-tokyo.ac.jp

Use the subject line:

[Security Report] Brief description of the issue

Please do not disclose the vulnerability publicly, create a public GitHub issue, or publish proof-of-concept material before the issue has been reviewed and, where appropriate, corrected.

Information to Include

Please include enough information to reproduce and evaluate the issue:

A clear description of the vulnerability

The affected page, file, URL, or component

The steps required to reproduce the issue

The potential security impact

Screenshots, logs, or proof-of-concept code, when relevant

Your name and preferred contact information, unless you wish to report anonymously

Any suggested remediation, if available

Do not include passwords, private keys, access tokens, personal data, confidential research data, or other sensitive information in the report.

Response Process

After receiving a report, the maintainer will aim to:

Acknowledge receipt within 7 days

Perform an initial assessment within 30 days

Request additional information when necessary

Correct confirmed vulnerabilities according to their severity and practical impact

Notify the reporter when the issue has been resolved or otherwise addressed

These timeframes are targets rather than guarantees because this is a personally maintained academic website.

Scope

Examples of issues that are generally considered in scope include:

Cross-site scripting or script injection affecting visitors

Unauthorized modification of website content

Exposed credentials, tokens, private keys, or confidential files

Unsafe external links or redirects controlled by this repository

Vulnerabilities in third-party scripts or resources directly included by the website

GitHub Pages or repository configuration errors that expose sensitive information

Security weaknesses that could mislead visitors about the identity, research, publications, or contact information presented on the website

Out of Scope

The following are generally outside the scope of this policy:

Vulnerabilities in GitHub, GitHub Pages, browsers, operating systems, or unrelated third-party services

Denial-of-service testing or attempts to disrupt website availability

Automated scanner reports without a reproducible security impact

Self-XSS that requires a user to paste code into their own browser console

Social engineering, phishing, impersonation, or physical attacks

Spam, content preferences, typographical errors, or broken links without a security impact

Issues affecting unsupported forks, copied versions, or old commits

Reports based only on missing optional security headers where no practical exploit is demonstrated

Service-level vulnerabilities affecting GitHub should be reported directly to GitHub through its official security reporting process.

Responsible Testing

Security research must be conducted carefully and in good faith.

When testing this website, you must:

Avoid accessing, modifying, deleting, or retaining data that does not belong to you

Avoid disrupting the website, repository, GitHub Pages, or other users

Avoid using destructive payloads, denial-of-service techniques, or excessive automated requests

Test only what is necessary to confirm the vulnerability

Stop testing and report the issue if you encounter sensitive information

Comply with applicable laws and GitHub's terms and policies

Disclosure

Please allow reasonable time for investigation and remediation before publicly discussing a reported vulnerability. Coordinated disclosure may be agreed upon after the issue has been assessed.

Credit may be provided to reporters who submit valid findings and request acknowledgment. No public credit will be given without the reporter's consent.

Bug Bounty

This project does not currently operate a paid bug bounty program. Submission of a report does not create an entitlement to payment, compensation, or other reward.

Safe Harbor

Good-faith research conducted in accordance with this policy will not be considered malicious by the project maintainer. This statement does not authorize activity against GitHub, third-party platforms, or systems outside the maintainer's control, and it does not override applicable law or third-party terms of service.

Policy Updates

This policy may be revised as the website, repository, hosting configuration, or security requirements change.
